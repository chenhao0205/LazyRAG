把输入的 query 提纯成 {unit, core, qualifier} 结构(unit 留原文,core / qualifier 为拆解结果)。query 整条恒为一个单元,不切分。

## §1 不变式
- 只依据输入文本提取,不引入外部知识或常识补全。
- 不核验事实、不判断内容对错、不补全原文未写明内容。
- 输出文本须来自输入原文或对其忠实改写,不弱化、加强、泛化或反转语义。

## §2 分解
core 与 qualifier 是同一unit的拆分,参考下方表格「典型成分」与「输出形式」，用相同**剥离测试**将 unit 拆解:
- 剥掉后指称改变(塌缩,或变成另一件事)→ 归 **core**(无法剥离)。
- 剥掉后指称不变、剥离元素隶属 qualifier → 归 **qualifier**(可剥离的)。

| 维度 | core | qualifier |
|---|---|---|
| 典型成分 | 主体-谓词-受事骨架 | 范围、极性、强度、依据 |
| 输出形式 | 一条最小完整命题 | 并成一句自包含限定命题;无则空串 |

补充约束:
- qualifier 仅承载范围 / 极性 / 强度类修饰,不承载额外独立事实。
- 仅当 query 自身含明确的范围 / 极性 / 强度修饰时才填 qualifier,否则 qualifier 为空串。

对照例(⟨…⟩ 为占位符,仅示范结构):
- 「⟨命题⟩,仅在⟨时间⟩」→ core「⟨命题⟩」、qualifier「该命题仅在⟨时间⟩成立」。(范围 / 时效)
- 「仅⟨主体⟩可⟨动作⟩」→ core「⟨主体⟩可⟨动作⟩」、qualifier「仅限⟨主体⟩(排他)」。(极性 / 强度)
- 「根据⟨出处⟩,⟨命题⟩」→ core「⟨命题⟩」、qualifier「⟨命题⟩根据为⟨出处⟩」(范围/依据)。

## §3 执行流
1. 把 query 原文逐字写入 `unit`(不改写)。
2. 对该 unit 执行 §2 分解 → 写出 core 与 qualifier;两者合起来须覆盖且不超出该 unit 的语义。

## §4 输出格式
严格输出一个 JSON 对象,不要 markdown 围栏,不要输出解释文本:

{
  "query": {"unit": "...", "core": "...", "qualifier": "..."}
}

## §5 硬性要求
- `unit` 为 query 原文逐字片段,不改写;core / qualifier 才可忠实改写。
- query.core 必须非空;qualifier 可为空串。
